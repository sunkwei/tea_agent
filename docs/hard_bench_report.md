## 四、棘轮机制（防未来退化）

除绝对阈值外，另设 5 条**棘轮**：基线 = 实测值，只允许变好、不允许变差。

```
except: pass ≤ 116 · 裸捕获 ≤ 747 · print ≤ 161 · TODO ≤ 24 · 超长函数 ≤ 26
```

价值：任何「为了让某功能通过而顺手多写一个 except: pass」的小动作都会触发失败。
这是把「代码质量」变成**可回归的约束**，而非靠自觉。

## 五、曲线结果与一个诚实发现

20 轮实验（14 回归 + 6 改进）在新基线下重跑：

```
score:    0.7826 → 0.8276   (+4.5pp)
coverage: 23     → 29
回归检出:  14/14            改进保留: 6/6
```

**诚实发现：口径分歧从 6 次归零。**
原先「同分改进被误判 no_change」的 pass-ratio 盲区，在基线上限被打破后**不再显现** ——
因为此时加一条通过的探针会同时抬高 ratio。

结论：**覆盖感知修复的价值只在基线饱和时体现**。这不是修复无意义，而是它的适用条件被精确界定了；
该场景由 `test_compare_coverage_only_improvement_is_keep` 直接覆盖，不依赖实验复现。

## 六、过程中的三次自纠（基准自己的 bug）

难度任务集上线后，先后暴露 **3 个属于「量具」而非「被测代码」的缺陷**：

| # | 缺陷 | 根因 | 修法 |
|---|---|---|---|
| 1 | `hard-approval-enforce` SyntaxError | `def` 不能跟在 `;` 之后 | 改为换行定义局部函数 |
| 2 | 棘轮基线有 6 单位盲区 | 探针口径（274 文件）≠ 基准口径（198 文件，排除 tests/demo） | 统一排除规则，基线重取为 116/747/161/24 |
| 3 | 20 轮实验断言 TypeError | `_run_bench`（子进程）返回 `failed` 为 **id 字符串列表**，我按 `run_bench` 的 **dict 列表**取 `f["id"]` | 统一按 `set(res["failed"])` 处理 |

教训：**量具本身也必须被校准**。一个从未失败过的基准，和没有基准是等价的 ——
这条在上一轮（14 轮回归只检出 8 轮）已被验证，本轮再次成立。
