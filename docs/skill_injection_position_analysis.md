# 技能注入位置优化分析：L3-L2 之间 vs 消息尾部

## 📊 当前架构 vs 建议架构

### 当前架构（动态上下文在尾部）
```
L0 系统提示词 → L3 语义摘要 → L2 相关历史 → 动态上下文 → L1 最新对话
                                    ↑
                          技能注入在此（消息尾部）
```

### 建议架构（技能注入在 L3-L2 之间）
```
L0 系统提示词 → L3 语义摘要 → 技能注入 → L2 相关历史 → L1 最新对话
```

## 🔍 详细对比分析

### 1. 模型可见性
| 方案 | 可见性 | 说明 |
|------|--------|------|
| **当前方案** | 中等 | 技能在消息尾部，模型需要回看 |
| **建议方案** | 高 | 技能在 L2 之前，模型优先处理 |

**结论**：建议方案在模型可见性上更优。

### 2. 缓存命中率影响
| 方案 | 影响 | 说明 |
|------|------|------|
| **当前方案** | 低 | L0/L3/L2 前缀稳定，动态内容变化只影响尾部 |
| **建议方案** | 高 | 技能注入变化会影响 L2 和 L1 的前缀 |

**量化分析**：
- 技能注入变化频率：中等（随对话内容变化）
- 影响范围：L2 和 L1（约占总 token 的 40-60%）
- 缓存命中率影响：预计下降 10-15%

### 3. 逻辑顺序
| 方案 | 逻辑性 | 说明 |
|------|--------|------|
| **当前方案** | 中等 | 动态内容在最后，但位置锚定合理 |
| **建议方案** | 高 | 符合：系统 → 摘要 → 技能 → 相关历史 → 最新对话 |

**结论**：建议方案在逻辑顺序上更优。

### 4. 实现复杂度
| 方案 | 复杂度 | 说明 |
|------|--------|------|
| **当前方案** | 低 | 已实现，只需维护 |
| **建议方案** | 中等 | 需要修改 build_api_messages 函数 |

## 🎯 折中方案：混合策略

### 方案 A：核心技能前置，动态内容后置
```
L0 → L3 → 核心技能提示（静态） → L2 → 动态技能内容（动态） → L1
```
- **优点**：平衡可见性和缓存
- **缺点**：需要拆分技能注入内容

### 方案 B：智能缓存策略
- **技能内容缓存**：技能包内容（SKILL.md）变化时才更新
- **加载决策缓存**：加载决策变化时才更新
- **位置不变**：保持当前尾部注入

### 方案 C：条件性前置
- **静态技能**：内容不变的技能前置到 L3-L2 之间
- **动态技能**：内容变化的技能保持尾部注入
