# 工具档位自适应 (Tool Profiles)

> 按模型上下文窗口（`max_context_tokens`）自动裁剪工具暴露量，为上下文受限模型释放可用空间。
> 2026-09-06 实现。

## 背景与动机

工具 JSON Schema 是**每次 API 请求都全额携带的固定开销**。实测当前 57 个 LLM 可见工具 schema ≈ 43KB ≈ 10.8K tokens：

| 模型窗口 | 全量工具占比 | 影响 |
|---|---|---|
| 256K | 4.2% | 可忽略，保留全量 |
| 128K | 8.4% | 可接受 |
| 64K | 17% | 明显占用 |
| 32K | 34% | 必须精简 |
| 8~16K | 100%+ | 不可用（需 nano） |

长会话多轮工具循环会把该固定开销放大几十上百倍（历史 token 统计中 prompt tokens 占 99.2%），因此**裁剪工具集是全链路降本**，不止省单次请求。

## 核心结论：不是「一刀切 3 个工具」

「仅提供 exec/file/edit 三个」太激进，会丧失 search/diff/memory/plan 等结构化能力。正确姿势是**按窗口分档**，且保证最后保底档位不丢：

```
ctx ≥ 200K            → full      （全部 57 个，能力优先）
64K ≤ ctx < 200K      → standard  （CORE 19 + 高频 ≈ 30）
32K ≤ ctx < 64K       → core      （编码闭环 ≈ 13）
16K ≤ ctx < 32K       → minimal   （exec/file/edit/diff/search/question ≈ 6）
ctx < 16K             → nano      （exec + file + edit，真正三件套）
```

| 档位 | 工具数 | ≈tokens/请求 |
|---|---|---|
| full | 57 | 10.8K |
| standard | 30 | 5.8K |
| core | 13 | 3.1K |
| minimal | 6 | 1.4K |
| nano | 3 | 0.8K |

## 架构约束：前缀缓存稳定性

DeepSeek 前缀缓存命中前提是工具 JSON Schema 顺序跨进程稳定（`llm_tool_names` 排序保证）。

→ **档位必须在会话启动时一次性选定，整个会话保持稳定**，禁止中途收缩/膨胀工具列表。意图级动态注入（`filter_tools` + `required_tools`）仅适合大窗口模型内部微调。

## max_context_tokens 来源链

```
① provider.yaml 模型条目 (context_window / max_context_tokens)   ← provider_store.resolve()
② config.yaml main_model 内嵌 max_context_tokens（显式覆盖 ①）
③ model_config.guess_model_config() 按模型名启发式推断           ← ①② 均缺省时
④ auto_compact.get_max_context_tokens() 兜底默认 1M             ← 最终保险
```

⚠️ 小模型若未显式配置窗口会走 ④ 得到 1M → profile 误判 full。因此 `resolve_tool_profile` 对**窗口未知（≤0）保守返回 full 并记 warning**，要求显式配置真实窗口或直接设 `tool_profile`。

## 实现

### 新模块 `tea_agent/tool_profiles.py`

- `PROFILE_THRESHOLDS`：窗口 → 档位阈值表
- `PROFILE_TOOLS`：每档工具名白名单（`full=None` 表示不过滤）
- `resolve_tool_profile(max_context_tokens, explicit="auto")`：推导档位（未知窗口→full；非法显式值→回退 auto 并 warning）
- `filter_tools_by_profile(tools, profile)`：按档位白名单过滤，保持原顺序

### 接入点

| 位置 | 改动 |
|---|---|
| `config.py` | `ModelConfig.tool_profile: str = "auto"`；解析/序列化（内嵌 + 引用式）+ config 模板注释 |
| `onlinesession.py` | `__init__` 加 `tool_profile` 参数；`_build_tools(tool_filter=None)` 常规路径按 profile 过滤（意图注入路径保留） |
| `litesession.py` | `__init__` 加 `max_context_tokens` / `tool_profile`；`_build_tools()` 按 profile 过滤 |
| `agent.py` | 构造 LiteSession / OnlineToolSession 透传 `tool_profile` |
| `server/modules/agent_module.py` | 同上（server 会话构造） |
| `toolkit_subagent.py` / `lite_agent.py` / `role_agent.py` | 子 Agent LiteSession 透传窗口与档位 |
| `context_fragments.py` | `_agents_md_budget()`：AGENTS.md 字节预算按窗口缩放（2K→16K，未知=16K 默认） |

### 能力边界提示

每个档位建议在系统提示词中声明能力边界，避免模型尝试调用不存在的工具（`full` 档无需）。

## 配置用法

```yaml
# config.yaml main_model 下
main_model:
  max_context_tokens: 32768   # ← 显式配置真实窗口（关键，避免 1M 兜底误判）
  tool_profile: auto          # auto=按窗口推导；可显式 full/standard/core/minimal/nano
```

`tool_profile` 也支持模型级引用式覆盖（仅显式设置时写入 config）。

## 测试

`tea_agent/tests/test_tool_profiles.py`（21 用例）覆盖：

- `resolve_tool_profile` 档位边界（0/未知、16K/32K/64K/200K）
- 显式档位优先；非法档位回退 auto
- 档位嵌套不变式（nano ⊂ minimal ⊂ core ⊂ standard ⊂ full）
- `filter_tools_by_profile` 过滤结果与顺序
- `ModelConfig.tool_profile` 读写 round-trip
- `_agents_md_budget` 预算随窗口单调不降（未知窗口单独保守用默认）

综合回归：相关模块 229 passed。
