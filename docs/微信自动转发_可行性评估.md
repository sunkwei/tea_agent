# 微信自动转发 — GUI 自动化可行性评估（实测）

> 场景：启动「微信自动转发」时，检查微信里有哪些未回复消息，把**未屏蔽**用户的未读消息转发到**文件传输助手**，格式 `用户: 消息`
>
> 评估时间：2026-09-20 · 环境：Windows 10 / 2560×1440 @200% DPI · 微信 4.x（Qt 5.15）
> 方法：**全部结论来自本机实测**（UIA 读取、原生滚轮、像素分析、写入回读），非纸面推演
> ⚠️ 评估过程已还原现场：前台窗口还给 Chrome、光标复位、输入框清空

---

## 0. 结论：可行，但需求正好落在最难的那一格

| 环节 | 结论 |
|------|------|
| 路径选择 | GUI 自动化是**唯一正当可行**路径 |
| 读会话列表 | ✅ UIA 可读，**无需激活无障碍** |
| 滚动枚举 | ✅ 可行，但必须 `SendInput` 原生滚轮（会抢前台） |
| 写入中文 | ✅ **完全打通**（UIA ValuePattern，无需剪贴板） |
| **读「未屏蔽」会话的未读数** | 🔴 **UIA 读不到 —— 需求恰好命中此处** |

> **一句话**：微信把「免打扰会话」的未读渲染成**文字**（可读），把「普通会话」的未读渲染成**头像个红气泡**（不可读）。而本需求要的正是后者。

---

## 1. 为什么只能走 GUI

### ❌ 官方 Bot 路径不适用

现有 `tea_agent/channel/wechat_adapter.py` 是 **iLink Bot 适配器**（腾讯 ClawBot 协议），架构是：

```
微信用户 → 微信App → iLink服务器 → 长轮询 → WeChatAdapter → tea_agent
```

它只能收到**发给机器人**的消息（实测会话列表中就是 `微信ClawBot`），**看不到用户的个人收件箱**。

### ❌ 本地数据库路径不可行

扫描 `Documents/xwechat_files/<user>/db_storage/`，**20 个库全部加密**：

| 库 | 头部（hex） | 状态 |
|---|---|---|
| `message/message_0.db` | `e9071bd8...` | 非 SQLite magic |
| `session/session.db` | `08b5323c...` | 非 SQLite magic |
| `contact/contact.db` | `623ee547...` | 非 SQLite magic |

`sqlite3` 直开一律报 `DatabaseError: file is not a database`（SQLCipher 加密）。解密需注入进程取密钥，**违反 ToS 且有封号风险**。

### ✅ GUI 自动化 = 唯一路径

## 2. 实测：微信 4.x 的 UI 结构

```
Weixin.exe (多进程: 主程序 + WeChatAppEx.exe/CEF 小程序容器)
└─ 主窗口  Win32类=Qt51514QWindowIcon   UIA类=mmui::MainWindow   标题=用户昵称
   ├─ mmui::MainTabBar        侧边导航（微信/通讯录/收藏/发现）
   ├─ mmui::XTableView        会话列表  [List]  120,194 538×1158
   ├─ mmui::RecyclerListView  消息列表  [List]  658,194 1894×878
   └─ mmui::ChatInputField    输入框    [Edit]  698,1090 1822×150
```

微信 4.x 是用 **Qt 5.15 + 自研 mmui 框架**重写的。关键：**Qt 无障碍桥默认开启**，`MainWindow` 下有 **158 个**可枚举后代节点——无需任何激活操作。

### 可用的 UIA Pattern（实测）

| 元素 | Selection | SelectionItem | Invoke | **Value** | Text |
|---|---|---|---|---|---|
| `XTableView`（会话列表） | ✅ | ❌ | ✅ | ✅ | ❌ |
| `RecyclerListView`（消息） | ✅ | ❌ | ✅ | ✅ | ❌ |
| `ChatSessionCell`（会话） | ❌ | ✅ | ✅ | ✅ | ❌ |
| `ChatInputField`（输入框） | ❌ | ❌ | ✅ | ✅ | ✅ |

**关键缺口**：三个列表控件**都不支持 ScrollPattern**，`ItemContainerPattern` / `VirtualizedItemPattern` 也不支持 → **无法通过 UIA 直接滚动或按需取项**。

## 3. 会话列表读取：✅ 完全可行

`ChatSessionCell` 是**叶子节点（0 个子元素）**——整行信息被序列化进 UIA `Name`，用 `\n` 分隔。实测原始值：

```
'成都高新服务【内部】群'
'[41条] 舟客: 这两个admin是分别是18号和19号新增的，可以跟现场老师确认下有没有印象新增用户'
'19:05'
'消息免打扰'

'京东自营好价通知群'
'[97条] 冬青: 【🔴26.9包邮】稻香村 丝苗米 南方籼米 5kg'
''
'https://u.jd.com/4aGGFKG'
'18:49'
'消息免打扰'
```

可稳定解析出 5 个字段：**标题 / 未读数 / 预览 / 时间 / 是否免打扰**（`已置顶` 亦同法解析）。

## 4. 滚动枚举：✅ 可行，但方式受限

| 方式 | 结果 |
|---|---|
| `PostMessage(WM_MOUSEWHEEL)` 到窗口/最深子窗口 | ❌ **无效**（Qt 只认真实输入事件） |
| `SetForegroundWindow` + `SetCursorPos` + `SendInput` | ✅ **有效** |

实测：前置微信后原生滚轮 10 格，会话列表**成功换页**，读到 4 个未读会话（41/97/58/7 条）。

**代价（必须处理）**：
- 会**抢前台窗口**（打断用户）
- 会**移动鼠标**（必须保存/还原光标位置）
- 可见区仅 ~8 个会话，需反复滚动 + 去重
- 列表会随时间重排（评估期间就观测到两次重排）

> 一个反面教训：`PostMessage` 测试中我一度误判"滚动成功"——实际是**新消息到达导致列表重排**，置顶会话仍在原位。判据必须是「置顶项是否位移」，而非「列表内容是否变化」。

---

## 5. 🔴 核心发现：未读数只在「免打扰」会话里可读

实测全量会话（滚动后 8 个）：

| 会话 | 未读数 | 免打扰 |
|------|:---:|:---:|
| 成都高新服务【内部】群 | **41** | ✅ |
| 京东自营好价通知群 | **97** | ✅ |
| 河北央馆研修平台内部支持群 | **58** | ✅ |
| （内部）贵州智能研修平台专班支持 | **7** | ✅ |
| 贵州边缘硬件内部交流 | — | ❌ |
| 测试-中庆&万物2R1828+1684X服务器 | — | ❌ |
| 公众号 | — | ❌ |
| 微信ClawBot | — | ❌ |

**规律**：能读到未读数的会话 **100% 都是「消息免打扰」**；非免打扰会话的未读数**一律为空**。

### 原因（微信 UI 约定）

| 会话类型 | 未读呈现方式 | UIA 可读？ |
|---|---|---|
| 免打扰 | 预览行**文字** `[N条]` 前缀 | ✅ 在 Name 里 |
| **普通** | 头像右上角**红色数字气泡**（QPainter 绘制） | ❌ **不在 Name 里** |

### 像素级验证

对会话列表截图做红色连通域分析（`r≥180, g≤90, b≤90`），检出 **4 个 26×26 红块**，屏幕坐标精确落在 4 个免打扰会话的 `[N条]` 位置 —— 证明红字就是"免打扰"标记本身。而普通会话的**头像区没有任何 ≥26×26 的红色区块**（仅有 11×5、12×6 这类噪点）。

> **这直接冲击本需求**：需求要的是"**未屏蔽**用户的未读消息"——恰好是 UIA 读不到的那一类。必须为普通会话补一条**像素/视觉**读取路径。

## 6. 写入路径：✅ 完全打通（含中文）

实测 `mmui::ChatInputField`：

```
value_pattern  = True
is_enabled     = True
write_ok       = True        ← SetValue("探测哪") 后读回一致
restored_to    = ""          ← 已还原为空
restore_ok     = True
```

**重要**：中文字符串**直接可用**，无需剪贴板注入。
这正好补上了上一轮评估发现的缺口——`pyautogui` 的 `KEYBOARD_KEYS` 中**非 ASCII 键为 0**，`type('中文')` 必然失败；而 UIA `ValuePattern` 绕开了整个键盘映射层。

## 7. 落地架构建议

```
┌─ 采集层（不碰鼠标）────────────────────────────┐
│ UIA 读 XTableView → 全部可见 ChatSessionCell   │
│  ├ 解析 [N条]      → 免打扰会话未读数（可靠）  │
│  ├ 解析 消息免打扰 → 屏蔽标志                  │
│  └ 无 [N条] 的普通会话 → 截图 + 头像区红点检测 │
│     （像素连通域 / 视觉模型兜底）               │
├─ 枚举层 ─────────────────────────────────────┤
│ 原生滚轮循环翻页 → 直到列表底部 → 按(标题+时间)去重 │
├─ 读取层 ─────────────────────────────────────┤
│ SelectionItemPattern.Select 进入会话            │
│ 读 RecyclerListView → 定位「未读分割线」→ 只取未读部分 │
├─ 转发层 ─────────────────────────────────────┤
│ 选「文件传输助手」→ ChatInputField.SetValue(    │
│   f"{user}: {msg}") → Invoke 发送 / Enter       │
├─ 安全层（必须先于功能落地）───────────────────┤
│ 桌面占用锁 · 光标/前台还原 · 消息去重(幂等)     │
│ 速率限制 · 熔断 · 干跑(dry-run)模式             │
│ toolkit_input 纳入审批+审计（当前为监管真空）   │
└───────────────────────────────────────────────┘
```

## 8. 风险清单

| 级别 | 风险 | 说明 |
|:---:|---|---|
| 🔴 | **未读语义错位** | 需求要的"未屏蔽"会话未读**读不到**，需补像素路径，准确率无法保证 100% |
| 🔴 | **抢用户桌面** | 滚动必须抢前台 + 移动鼠标，用户正在用电脑时体验很差 |
| 🔴 | **`toolkit_input` 零审计** | 上一轮已发现：不在任何风险清单，无审批无审计。此场景会放大该风险 |
| 🟠 | **合规/封号** | 个人微信 GUI 自动化非官方支持，存在风控风险；官方仅 iLink Bot 路径合法 |
| 🟠 | **幂等性** | 重复运行会重复转发；需按消息内容 hash 去重 |
| 🟠 | **消息归属** | 需区分"别人发的"与"自己发的"，且需处理撤回/编辑 |
| 🟡 | **无 TextPattern** | 消息正文需逐个进入会话读取，无法批量 |
| 🟡 | **窗口状态依赖** | 微信最小化/被遮挡/列表重排都会影响结果 |
| 🟡 | **编码陷阱** | PowerShell 读中文脚本需 UTF-8 BOM，否则中文正则失效（实测踩坑） |

---

## 9. 建议

1. **先做可行性验证（PoC）**：只读模式跑通「枚举 + 解析 + 红点检测」，人工核对准确率
2. **优先补齐安全护栏**：`toolkit_input` 纳入 `high` 风险 + 审计；加桌面占用锁、光标还原、干跑模式
3. **分级策略**：
   - 免打扰会话 → UIA 文本路径（可靠）
   - 普通会话 → 截图红点检测（需实测准确率）
4. **合规提示**：向用户明确 GUI 自动化的风控风险，默认**关闭**，需显式授权
5. **长期方向**：引导用户把需转发的会话接入**官方 iLink Bot**，从根本上避开 GUI 自动化
